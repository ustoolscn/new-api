# 渠道用量调整

渠道编辑的高级设置提供“用量调整”，默认关闭。配置保存在现有 `channels.setting` JSON 的 `usage_adjustment` 中，不新增数据库表或列。

```json
{
  "usage_adjustment": {
    "enabled": true,
    "cache_min": -30,
    "cache_max": -10,
    "output_min": 0,
    "output_max": 10
  }
}
```

上下限都是百分比，范围为 -100 到 +100，下限不能超过上限。相同上下限表示固定比例；否则每个成功上游响应各抽取一次缓存和输出比例，整个流式响应共用该比例。重试选择的新渠道使用自己的规则。

## 数量与计费

- 缓存比例作用于**缓存读取**，不调整缓存创建量。减少的缓存读取量转入普通输入；增加的缓存读取量从普通输入转入，最多转到普通输入为零。总输入始终不变。
- 例如普通输入 20,000、缓存读取 130,000：缓存 -30% 后分别为 59,000 和 91,000，总输入仍为 150,000。
- 输出独立乘以 `1 + 抽中比例 / 100`，使用项目统一四舍五入与饱和保护；输出 -100% 可以得到零，不能触发本地估算将其补回。推理输出明细同步调整。
- Anthropic 的 `input_tokens` 是普通输入；OpenAI 的 `prompt_tokens` / Responses `input_tokens` 包含缓存，不能把缓存差额再次加到这些总输入字段。Gemini 保留工具输入并同步调整思考输出。
- 调整在文本上游响应进入适配器前进行，使协议转换、客户端 usage、普通/表达式计费读取相同的调整值。已有价格、倍率和订阅结算规则继续生效。预扣额按输出比例上限保守估算，实际按抽取后的用量结算。
- 客户端 `usage` 表示本渠道的**计费用量**，不再表示未经调整的上游计数。已有日志不会重新计算或补扣。

## 范围

接入 Chat Completions、Claude Messages、Responses 和 Gemini 文本处理入口，识别标准 JSON/SSE usage；不修改消息内容、工具参数或请求体。图像、音频专用入口、Embedding、异步任务、Realtime 不使用此调整。启用后非 JSON/SSE 或未解压的上游响应会报错，不猜测二进制用量；缺少上游 usage 时保留原有估算路径，并记录 `no_upstream_usage`。提供商自定义用量格式应先进行兼容性验证。

单个 JSON 响应或 SSE 事件上限 64 MiB；流式只缓冲一个事件。异常负值、非整数或超过 int32 的上游计数被拒绝。输出扩大导致饱和时写入现有 `quota_saturation` 审计信息。

## 审计与权限

管理员日志详情的“用量调整审计”显示规则区间、本次抽中比例、处理状态，以及各协议表示的原始/调整后总输入、普通输入、缓存读取、缓存创建和输出。

数据位于 `other.admin_info.usage_adjustment`，只保存数量和规则，不保存请求正文或密钥。普通用户日志沿用既有过滤，移除整个 `admin_info`；普通日志数量和扣费是调整后的结果。

关闭开关后恢复既有处理，不改变此前的用量或账单。上线代码本身不会开启任何渠道的调整规则。
