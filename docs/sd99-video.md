# SD99 视频通道

SD99 使用独立渠道类型 `59`，适配器位于 `relay/channel/task/sd99/`。协议依据本地交付的《SD99 · video-sd-2.0(TC) 接口接入文档》（2026-10-25）；不复用火山原生视频或 Sora 的请求转换。

## 管理后台配置

1. 新建渠道，类型选择 **SD99**。
2. API 地址填 `https://api.sd99.vip`；也支持末尾带 `/v1`，不会重复拼接版本路径。
3. 密钥填自己的 SD99 API Key；支持现有渠道多密钥配置，任务保存实际提交使用的密钥，后续查询和下载继续使用该密钥。
4. 模型填精确名称 `video-sd-2.0(TC)`。可以通过模型映射向下游提供别名。获取上游模型通过带认证的 `/v1/models`，以自己账号的授权结果为准。
5. 在模型定价中配置按次价格，或 `billing_mode=video_seconds` 及 480p/720p/1080p 的每秒零售价。未配置按次价格时不支持用 Token 倍率替代；SD99 供应商的 Token 成本不等于本站零售价，不内置未经核实的价格。
6. 如果需要模型广场展示视频调用入口，在模型元信息中显式配置 `openai-video` 端点，遵循现有端点展示规则。

渠道的通用聊天测试不支持此视频通道，避免测试按钮意外提交收费生成。请手动提交一个最小视频任务联调。

## 创建、查询、下载

下游统一入口为 `POST /v1/video/generations`，兼容 `POST /v1/videos`；查询、成品下载均使用本服务返回的公开 `task_...` ID：

```http
GET /v1/videos/{id}
GET /v1/videos/{id}/content
```

普通生成请求：

```json
{
  "model": "video-sd-2.0(TC)",
  "prompt": "黄昏海边，海浪轻拍沙滩，镜头缓慢推进。",
  "duration": 5,
  "metadata": {
    "ratio": "16:9",
    "resolution": "480p",
    "generate_audio": false
  }
}
```

普通生成时长为整数 5–15 秒，省略默认 5 秒；分辨率支持 `480p`、`720p`、`1080p`，默认 `480p`；比例支持 `16:9`、`9:16`、`1:1`、`4:3`、`3:4`、`21:9`，默认 `16:9`。`generate_audio` 保留布尔类型，显式 `false` 不会丢失，省略表示上游默认。未知 metadata 扩展字段不会转发，避免内部字段和其他协议参数进入本通道。

支持统一字段 `seconds`、`size`、`images`、`input_video(s)`、`input_audio(s)` 和 `generate_audio`；这些字段被转换为上述 SD99 结构。不要同时提供内容互相矛盾的标准字段和 metadata 字段。该协议不支持自定义 FPS，因此不使用客户端 FPS 调整费用。

参考素材放在 `metadata.content`，最多 9 张图片、3 段视频、3 段音频；使用 HTTPS 直链，每项 URL 单独提供。完全重复的 URL 去重并保持顺序。音频参考必须同时提供图片或视频。

```json
{
  "model": "video-sd-2.0(TC)",
  "prompt": "参考图片场景，借鉴视频运镜和音频氛围。",
  "duration": 5,
  "metadata": {
    "ratio": "16:9",
    "resolution": "720p",
    "content": [
      {"type":"image_url","role":"reference_image","image_url":{"url":"https://media.example.com/a.jpg"}},
      {"type":"video_url","role":"reference_video","video_url":{"url":"https://media.example.com/a.mp4"}},
      {"type":"audio_url","role":"reference_audio","audio_url":{"url":"https://media.example.com/a.mp3"}}
    ]
  }
}
```

以上媒体 URL 均为占位地址。仅支持 JSON + URL，不支持 multipart 文件或本地素材地址。

## 编辑源视频

使用 `duration=-1`、`metadata.ratio="adaptive"`，恰好提供一段 `reference_video`。可以添加数量限制内的图片和音频辅助参考。不使用 `/remix`。

本站先通过已有 SSRF 防护和有界范围请求探测源片真实时长，要求为 4–15 秒；探测失败拒绝提交。向上游发送的仍为 `-1`，本站计费只使用真实时长向上取整后的正数秒数；客户端声明的 `input_video_seconds` 不作为可信来源。按秒计费还可按模型配置独立收取输入视频费用，沿用统一视频计费链路。

## 任务和错误处理

- 创建识别 `id`、`task_id`、`job_id`，任务号校验为 `[A-Za-z0-9_-]{1,128}`，下游拿到的是本站公开 ID。
- 查询识别文档约定的等待、执行、完成及失败状态别名，忽略大小写和前后空格。
- 查询的 `fail_to_fetch_task` 优先作为临时查询异常；未知状态、非 JSON、HTTP 非 2xx 保留原任务，后续查询不创建新任务。
- POST 一旦开始发送，不自动切换渠道、密钥或重放；也不跟随创建响应的重定向。网络错误、无有效任务号或业务错误返回提交异常；结果不明时必须先核对供应商记录。
- 已确认生成失败沿用本站异步任务失败退款规则；这只表示本站退款，不代表供应商账单已退款。
- SD99 等待超时不视为供应商生成失败；继续保留原任务查询，不按通用任务超时规则自动失败退款。
- 成品下载优先按文档顺序查找输出直链、视频数组项和 `download_url` / `content_url`，相对地址按服务根域解析；无直链时回退到原任务 `/content`。
- 结果统一通过本站成品代理提供；仅向同源且路径匹配原任务的 `/content` 发送任务保存的供应商 Key。外部直链及跨域重定向不携带该 Key。下载排除空文件和 HTML/JSON 错误页；下载失败只重取原任务成品。

任务记录与后台轮询沿用现有数据库机制。本站目前在创建成功返回后插入任务；如果提交响应丢失、进程在提交期间退出或任务保存失败，仍需人工核对供应商记录，本适配器不承诺上游幂等或跨进程自动恢复未知提交。成品代理不自动归档到对象存储，长期保存需由调用方完成。

## 验证边界

自动化测试使用本地模拟响应，覆盖请求结构、素材限制、时长边界、编辑时长隔离、状态别名、查询异常、创建禁重试、地址解析和凭据范围。真实账号权限、生成质量、各分辨率、多素材组合和编辑能力需使用供应商账号单独联调；本次开发不提交收费生成。
